# 09｜学生任务、不可变提交与成绩

[本地 tracker 与执行约定](development.md) · [字段字典](database.md) · [接口契约](interfaces.md)

## Problem Statement

学生需要知道作业到底有没有交上；重交后，教师应能找到被评分的那份源码。

## Solution

学⑤～⑦按班级领取任务，保存不可变提交版本；同一版本同时用于批改、授权静态评审和个人成绩查询。

## User Stories

1. 作为学生，我希望读取自己的任务要求和截止时间，以便知道要交什么。
2. 作为学生，我希望上传源码、压缩包、截图和说明，以便保留完整实验结果。
3. 作为学生，我希望在截止前重交并回看历史，以便明确教师批的是哪一版。
4. 作为教师，我希望从指定提交选择包内源码，以便评审有稳定的文件编号。
5. 作为学生，我希望分别看到待批、0 分和评语，以便正确理解成绩。

## Implementation Decisions

- S1 在事务内校验名单、当前授权、截止时刻与附件所有权，锁定应交记录后分配 revision。提交成功才写 E1。
- 不可变 submission_id 与 file_id 组成读取依据；S2 列文件，S3 校验归属后读有界 UTF-8。保存原包，包内合法源码使用独立编号。超限、重复成员、越界路径及链接按文件边界处理。
- 任务列表取最新提交，T4 按版本读成绩。上传失败不推进业务状态，重新提交产生新版本。
- 对接范围：S1～S3 → T2/T4、F1、E1；submissions、submission_files。

## Testing Decisions

通过学生入口重交两次再按旧编号取文；并发提交版本唯一，截止后 409，换账号或混配附件 404；用 0 分与未批验证历次成绩页。

## Out of Scope

| 本模块范围外 |
|---|
| 执行学生程序、由学生提交接口写教师评分 |

## Further Notes

单文件评审上限 512 KiB；实际整包大小、成员数与展开总量由 1、9 号按目标存储确定。
