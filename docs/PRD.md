## 2. 最终使用场景和已知边界

学生从案例库进入一个案例，阅读原理与代码，用自己的图片运行课程算法，看到真实结果；遇到问题可以问助教。教师用同一案例布置实验或作业，批改学生提交物，查看成绩与班级学习情况。管理员管理用户、权限和平台运行状态。助教既能从平台内进入，也有独立入口；建议两个入口复用身份和能力。

**范围依据：** 分工表列出 15 个案例、15 个算法接入和九项分工；三张原型描述入口，群内答复明确下列行为。业务流程按本版及配套规格执行；技术选型与外部资源条件见第 4、5 节。原型示例数据、日期和旧产品名不进入真实业务。

| 范围 | 实施边界 |
|---|---|
| 教学材料 | 已知来源为实验室服务器；案例、代码、数据集、环境逐项登记，缺件由 2、3 号跟进。 |
| 检索与理解 | 讲义、代码、习题分别切分。先实现文本与代码检索，再接图片、标注图和训练曲线理解；原理文档支持 Markdown 和 ipynb。 |
| 学生代码 | 9 号作为作业附件保存；7 号仅在本地做静态分析，向教师提供带理由的建议。 |
| 算法与教学状态 | 3 号运行预封装算法，独立进程执行、按容量排队；运行成功记为实验记录，学生显式提交记为作业提交，教师评分记为成绩。 |

## 3. 九个人各交付什么

下文“学、师、管、独”分别代表学生端、教师端、管理员端、独立助教；数字是原型页号。每个编号拥有本模块的页面或页内功能、对应业务逻辑、必要数据和验证样例。

### 1 号｜平台基础、身份权限和数据库（学①、师①、管①～④）

- **最终交付：** 统一登录、三个角色首页、管理员用户管理与启停、角色权限管理及权限说明；首页统计读真实模块数据，无数据时显示空状态。统筹全库结构与迁移，各模块提出并维护本领域字段。管理员能到达所有功能入口；访问学生个人数据仍须有对应的数据权限。
- **交给谁：** 给全组一份当前用户、角色和可访问班级的示例；给 4、8、9 号可用的班级与师生关系。默认支持预置示例班级。与 6 号约定平台健康状态来源；管理员页面归 1 号，部署运行配置归 6 号。
- **做完的证据：** 学生看自己、教师看所教班级、管理员按授权管理用户。学生直接请求管理接口仍被拒绝；禁用账号后不能继续访问受保护数据。空库可按说明初始化。

### 2 号｜案例学习与案例库（学②③、师②③，共用）

- **最终交付：** 15 个案例的录入、列表检索与分类、详情和版本管理；详情可看原理、代码、数据集与习题，并能启动相应实验。Markdown / ipynb 可阅读，展示 notebook 不执行单元格。
- **交给谁：** 给 3、4、5、6 号稳定的案例编号、版本和对应算法；给 5 号可索引的材料及来源位置。先盘点 15 项：每项写明材料、运行入口、缺什么、由谁补；缺件显示“未提供”。
- **做完的证据：** 同一案例从学生端和教师端打开指向同一版本；从详情进入正确实验。案例更新后，已发布任务和历史引用仍可定位原版本。

### 3 号｜在线实验与算法执行（学④、师④，共用）

- **最终交付：** 图像上传、参数设置、15 个预封装算法的接入、结果与运行记录。每种算法列明输入格式、参数范围、默认值、输出及运行限制；调度按实际 CPU/GPU 资源限并发，繁忙时排队。
- **交给谁：** 给 2、6 号算法清单；给实验页与 6 号同一套提交、查状态、取产物的能力，不做两套执行器。向 8 号提供运行事件，向 6 号交付依赖和启动方式。
- **做完的证据：** 15 个算法各有一组可重复的输入、参数和预期输出特征。用两个账号同时提交，能区分任务、查回各自结果；非法参数不入队，失败或超时结束并说明原因，不无限转圈。

### 4 号｜教师教学任务与批改（师⑤～⑦）

- **最终交付：** 向所教班级发布实验或作业，填写关联案例、提交要求、截止时间；按任务查看未交、待批和已批学生，给分并写评语，按作业查看成绩。
- **交给谁：** 与 9 号共用同一份任务、提交和成绩记录，与 1 号共用班级。默认到期后停止提交；截止前可重新提交，以最后一次为待批版本并保留历史。批改后学生可见成绩。提交和评分分别绑定不可变版本。
- **做完的证据：** 教师发布后只有目标班级看到任务；教师能读到学生实际提交的附件，批改后学生端显示相同成绩与评语。未提交与已批 0 分能分开显示。

### 5 号｜RAG 知识库与问答（学⑧、师⑨问答、独⑥）

- **最终交付：** 从 2 号材料建索引，按概念、原理、代码或调参需求作答并标来源。讲义按章/知识点切，过长再分段；代码按文件与类/函数切，保留符号名；习题按整题切，题干与答案分开控制可见性。notebook 保留单元格顺序及相邻解释。
- **检索方案：** 每个片段保存案例/版本、来源位置、材料类型和可见范围。用适合中文课程文本和代码的嵌入模型将片段向量化，记录模型版本；查询用同版本模型，限制可见范围后返回最相关片段。对比单纯关键词检索，尤其检查算法名、函数名和参数名。材料或模型变更后更新对应索引。
- **交给谁：** 给 6、7 号交付“最终回答 + 可定位引用 / 资料不足”；内部保留命中片段供评测。输入包括问题、当前案例版本及服务端给出的可见范围。
- **做完的证据：** 建人工标注题集，覆盖讲义、代码、习题及无依据提问。建议每类至少 5 题；有依据题分别报告“前三条至少一条正确”的题数/总数（建议 ≥80%）和答案有材料支持的题数/总数；无依据题逐题检查不编造，学生不可检索受限答案。再用获准样例分别验证普通图片、标注图及训练曲线的解释，分项记录输入和依据。

### 6 号｜Agent 意图识别、算法工具调用与线上部署（师⑨算法、独⑦）

- **最终交付：** 接到自然语言请求，区分“问原理”和“实际运行”，已有明确页面操作时不让模型重复猜意图。问原理交给 5 号；想运行则核对算法、图片和参数，缺必要信息时追问，齐备后调用 3 号，并能按运行编号取回真实结果。评审和学情请求转到 7、8 号相应能力，仍检查权限。
- **交给谁：** 给 7 号统一的助教调用约定，给 8 号意图与工具结果事件。提供可复查的 Prompt 和工具说明：有哪些工具、何时调用、禁止行为、出错怎么答。模型只能选择允许的工具；身份、文件访问和参数范围由服务端校验。
- **部署交付：** 各号提供模块依赖、启动命令、配置项、持久数据位置和最小验证方法；6 号整合目标环境配置、启动/停止、健康检查、日志位置及备份恢复步骤。确认目标机、GPU/驱动、网络、模型服务及数据外发许可后做真实部署，不把实验室原环境直接升级为候选版本。
- **做完的证据：** “Canny 的原理？”不会启动算法；“帮我处理这张图”在输入不明时追问；明确请求能得到 3 号真实任务与产物；拒绝运行学生脚本。最终在获准目标环境走通登录、问答、实验及作业主链，重启后保留必要数据。

### 7 号｜代码静态评审与独立助教入口（师⑨评审、独⑤及⑧评审）

- **最终交付：** 独立首页整合知识问答、算法调用、代码评审、学情分析，按身份显示入口；教师助教页承载问答、算法和评审三个功能。独立首页/导航由 7 号整合，各项业务复用原负责人实现。
- **输入输出：** 输入代码文本或获准读取的作业文件、可选参考实现；输出问题位置、类别（可能的正确性问题/规范/与参考差异）、理由、修改建议。参考缺失时仍给静态建议，差异状态为 no_reference。教师从批改页带入选定提交和文件，读取评审建议后在 4 号模块评分。
- **做完的证据：** 同段示例代码在不同入口得到同一评审能力；能指出一个具体问题的位置及原因，处理空输入和缺参考情形。独立入口不能绕过作业权限。

### 8 号｜学情分析与教师周报（师⑧、独⑧学情）

- **最终交付：** 收集第 4 节约定事件，展示完成情况、高频问题、趋势并生成教师周报。注明班级、时间区间、分子分母和数据截止时间，不用活动量推断掌握程度。
- **交给谁：** 把事件需求发给 3、4、5、6、9 号；同一事件只认一个源头。向 7 号提供独立入口中的学情功能，向 1 号提供首页需要的统计。班级数据默认仅授权教师可查；学生不能通过独立入口查看他人表现。
- **做完的证据：** 用可手算样例核对：某实验任务布置给 4 人，2 人提交（一人提交两次），完成率为 2/4；无分母显示“暂无数据”。周报引用同一组统计，切换班级后不能混入其他班级。

### 9 号｜学生任务、提交和成绩（学⑤～⑦）

- **最终交付：** 查看分配给自己的任务、要求与截止时间；按教师要求上传代码压缩包、结果截图及说明；查看历次提交和本人已批成绩。文件保存为作业附件，不执行其中代码。
- **交给谁：** 将可批改的提交版本交给 4 号，与其共用截止及重提规则；提交成功才产生供 8 号使用的提交事件。
- **做完的证据：** 上传失败不显示“已提交”；成功后刷新能查回；更换账号不能查看他人的附件和成绩。教师尚未批改时显示“待批改”，不显示 0 分。

## 4. 编写字段与接口清单时要落实的业务约定

**同一件事只保留一个事实来源。** 以下是逻辑字段，不预设必须拆成九个服务。可以先用固定样例开发，但样例必须标明模拟；最终按真实模块的输出核对。

| 对接项 | 提供方 → 使用方 | 默认约定 |
|---|---|---|
| 用户与班级 | 1 → 全组 | 登录态解析出用户、角色、班级关系；从服务端核验资源归属，不接受客户端自报的教师或管理员身份。 |
| 案例与文件 | 2 → 3/4/5/6；上传模块 → 有权读取方 | 案例编号 + 版本定位教学材料，文件编号定位上传物；不在接口中传任意磁盘路径。 |
| 算法运行 | 3 → 实验页/6 | 提交：算法编号/版本、输入文件编号、参数 → 运行编号及状态。查询：排队 / 运行中 / 成功 / 失败；成功返回产物编号和耗时，失败含原因（如参数不合法、超时或资源不足）。无权读取不返回产物。 |
| 问答、评审及展示 | 5/7 → 助教入口；6 → 算法调用入口 | 回答带资料引用，算法结果带运行编号，评审带代码位置；页面只展示相应类型的证据。无资料、未运行、未评审分别显示。 |
| 教学任务 | 4 ↔ 9，8 只读统计 | 教学任务编号关联班级、案例版本、类型、截止时间和提交要求。提交编号关联学生、任务、版本、附件和提交时间；成绩绑定已批的提交版本。**教学任务编号和算法运行编号不是同一个东西。** |
| 学情事件 | 业务源 → 8 | 事件编号、事件类型、发生时间（含时区）、用户编号、所属班级/案例版本/教学任务/运行编号（按适用填）、状态，问答可附知识点标签。按事件编号去重；不默认记录完整提示词、学生代码、原图或密钥。 |

**统计口径：** 实验完成率按所选班级和实验教学任务，取“已有效提交的学生－任务对数 / 应提交的学生－任务对数”；运行成功率另算“成功运行数 / 已结束运行数”。高频问题按区间内不同提问事件的知识点标签计数，趋势按周比较同一口径；无标签归为未分类。周报展示统计范围、任务完成情况、成绩分布、高频问题和据此提出的教学建议。日志访问范围与保留期由 1、8 号在使用真实学生数据前落实。

**本轮开发基线：** 平台使用 Python 3.12 + Flask、Vue 3 + TypeScript、JWT、PostgreSQL 16；SQLAlchemy 2.x 定义模型，Alembic 统一建表和升级，psycopg 3 连接数据库。教学算法保留独立运行环境。RAG 使用 Sentence-Transformers 与 pgvector；6 号维护一个 SDK 工具循环。Docker 分离数据库、应用、网关和算法进程。GitHub 协作、人工审查与 Angular 提交规范沿用原提案；Redis、Prometheus/Grafana 按实际运维需要采用。见[工程决策和工单入口](development.md)。

## 6. 成品与答辩按什么检查

最终交付包含可访问的平台、可复现的启动及恢复说明、15 项案例与算法对照清单、四项原始设计成果（编排流程、知识库与评测、Prompt 与工具接口、事件与指标定义），以及下列场景的实际结果。开发中先取一个完整案例打通接口，最终按全部 15 项清单交付和答辩。

1. **学与练：** 学生找案例、读原理和代码、运行算法、对照输入与输出；查问课程内容能定位材料。再从助教请求同一算法，两个入口的结果都可追溯到运行记录。
2. **教与评：** 教师布置任务，指定班级学生提交，教师批改，学生看到相同成绩与评语；静态评审给出理由但不执行代码、不替教师给分。
3. **分析与管理：** 切换班级与时间范围，核对完成率、高频问题和周报；用学生身份尝试查看其他人的提交或教师周报时被拒绝。管理员能查运行状态并管理用户。
4. **完整性与失败：** 按清单核对全部案例、算法及相应真实产物；单列检索与多模态材料的覆盖结果。展示一次无资料回答及一次失败运行；两者都不伪造成功。保留测试输入、版本和复现步骤，缺项标明原因。
