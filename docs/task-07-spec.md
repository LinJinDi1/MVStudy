# 任务七 Spec｜代码静态评审与独立助教入口

状态：v0.1，供评审。计划放在仓库的 `docs/task-07-spec.md`。需求依据为 [项目 PRD 第 3 节任务七及第 4 节接口约定](https://github.com/chiffontopia/MVStudy/blob/main/docs/PRD.md)。

## 1. 交付与职责

| 位置 | 七号交付 | 对接 |
|---|---|---|
| 教师⑨ | 七号负责共用页面框架、问答／算法／评审三个入口的接入与联调，并实现代码评审区。评审区可从批改场景带入选中的提交版本和代码文件 | 四号提供批改入口，五号提供问答能力，六号提供算法调用能力 |
| 独⑤及独⑧评审 | 独立助教首页、导航和评审入口。按登录身份展示功能；两个评审入口使用同一评审 API 和规则 | 一号提供身份和班级授权 |
| 独立首页其他功能 | 问答、算法和学情入口及加载、空结果、失败和无权状态 | 五号返回回答和引用；六号提供算法运行入口及任务状态；八号提供学情摘要 |

代码评审交付可定位的规范提示、潜在正确性问题和可选的参考实现差异。每条提示包含代码位置、判断理由和修改建议。教师在四号模块中给分并保存评语。学生提交在本模块中只作为文本读取；评审过程不导入、不执行学生代码，也不把代码传给算法执行器或外部模型。独立首页的算法入口只使用六号的已登记算法能力。

## 2. 用户流程

1. 教师从教师⑨的评审区或独立助教入口打开评审；从批改页进入时带入已选择的提交版本和文件编号。
2. 用户粘贴代码，或选择自己有权评审的代码文件。若本次教学任务有获准使用的参考实现，页面可提供参考对比。
3. 页面显示检查状态及结果。问题卡片显示文件、行号、类别、理由和修改建议；空结果显示“当前规则未发现建议”。
4. 参考对比显示新增、删除和上下文行。未提供参考时，静态评审照常返回，页面显示“未提供参考实现”。差异与静态建议均不用于自动给分或判定代码已通过测试。

已授权教师可在所教班级内使用作业模式。助教角色和授权范围由一号确认。粘贴评审记录默认仅创建者可查；作业评审记录按原提交的当前权限读取。首页入口可见性由登录身份决定，API 对每次请求单独核验权限。

## 3. 七号 API

正式联调使用平台统一登录身份。以下路径沿用当前原型，作业文件模式、正式权限、持久化和差异状态是新增契约。四号、六号和两个评审页面复用此业务能力；同一后端内可通过服务函数复用，接口约定不要求拆成多个部署服务。

| 方法与路径 | 输入 | 成功响应 |
|---|---|---|
| `POST /api/reviews` | 粘贴模式传 `source`、可选 `language`（默认 `python`）；作业模式传 `submission_id`、`file_id` | `201`，返回评审记录和 `review_id` |
| `GET /api/reviews/{review_id}` | 评审编号 | `200`，返回与创建接口同结构的评审记录 |
| `POST /api/reviews/diff` | 文本模式传 `before`、`after` 两段文本；作业参考模式传 `submission_id`、`file_id`、`reference_file_id` | `200`，返回差异状态、计数及详情 |

- 两种输入形式分别使用。作业模式不接受客户端提供的代码内容、磁盘路径或 URL。后端用提交编号和文件编号读取指定版本的快照，并验证附件属于该提交及调用者能读取它。
- 正式版先保证 Python 的具体规则；其他语言只有实际实现的检查才在页面上标明。静态规则可以提示疑似风险，问题类别使用 `potential_correctness` 和 `style`。参考差异作为独立结果显示。
- 参考对比以参考实现为旧侧、学生提交为新侧，计数在截断前完成；替换一行按删除一行和新增一行计。缺少 `reference_file_id` 时返回 `status: "no_reference"`，计数为 `null`、`diff` 为 `[]`、`truncated` 为 `false`。显式给出不存在或无权读取的参考编号时返回错误。完成时 `status: "completed"`，`truncated` 表明差异详情是否被截断，`diff` 最多返回 1000 项。
- 评审成功后保存规则版本、创建者、创建时间、输入来源、对应提交/文件编号和结构化建议。粘贴模式下两个作业编号为 `null`。原始代码由提交模块管理；评审记录不复制整份代码。日志只记录请求标识、状态及必要元数据。

### 作业评审示例

请求体：

```json
{
  "submission_id": "sub_102",
  "file_id": "file_301"
}
```

响应关键字段：

```json
{
  "review_id": "rev_001",
  "submission_id": "sub_102",
  "file_id": "file_301",
  "language": "python",
  "status": "completed",
  "rule_version": "1.0",
  "findings": [
    {
      "rule": "python/bare-except",
      "category": "potential_correctness",
      "severity": "warning",
      "file": "main.py",
      "line_start": 8,
      "line_end": 8,
      "title": "捕获范围过宽",
      "description": "裸 except 可能掩盖原始错误。",
      "suggestion": "根据预期错误指定要捕获的异常类型。"
    }
  ],
  "is_ai_assisted": false,
  "execution_performed": false,
  "created_at": "2026-11-18T09:00:00Z"
}
```

行号从 1 开始。未发现提示时 `findings` 为 `[]`。错误结构统一为 `{"error":{"code":"invalid_source","message":"请输入有效代码文本。"}}`。字段缺失、输入形式冲突、空代码或不支持的语言返回 `400`；未登录返回 `401`；记录或附件不存在、附件不属于该提交、调用者无权读取相关资源时返回 `404`；请求体超限返回 `413`。原型的请求体上限为 512 KiB，正式附件的文本读取上限需与上传模块确认。

## 4. 需对齐的跨模块接口

| 提供方 | 七号需要的内容 | 待确认 |
|---|---|---|
| 一号 | 服务端身份、角色、班级关系及资源授权能力 | 助教是否可评审被分配班级的作业，账号禁用和班级授权撤销后何时生效 |
| 四号、九号 | 四号从批改上下文传 `submission_id` 和 `file_id`；九号提供给有权服务读取的提交及代码文件信息 | 提交版本、文件归属、语言、名称、编码和有限大小的文本。压缩包内单文件的稳定编号和读取方式待双方约定，可先用单个 Python 文件联调 |
| 教学材料与教师任务模块 | 参考实现的编号和授权读取能力；参考实现应和教学任务使用的版本对应 | 四号与二号确认参考实现由谁提供、如何绑定版本及谁可读取；未确认前使用虚构文本联调 |
| 五号 | 回答、可定位的引用、资料不足状态 | 七号在教师⑨和独立助教入口接入同一问答能力，展示五号返回的最终回答 |
| 六号 | 统一助教调用约定；算法返回运行编号、状态和结果入口；自然语言评审请求可转到七号 | 七号将算法调用接入教师⑨和独立助教入口，与六号确认调用格式及错误映射。六号负责工具编排，三号负责算法执行 |
| 八号 | 按授权班级和时间范围提供学情摘要 | 确认入口可见角色及展示字段 |

跨模块提案：原 PRD 约定“与参考实现比较” → 建议后续可扩展“同一学生、同一作业两次提交比较”，用于教师观察修改变化 → 影响 4、7、9 号。该提案单独评审，本 Spec 的验收按现行 PRD 保留参考实现比较。

## 5. 验收场景

| 场景 | 预期 |
|---|---|
| 教师⑨和独立入口分别输入同一段含裸 `except:` 的示例代码 | 两处展示相同的规则、行号、理由和建议；评审编号独立生成 |
| 空代码、非法字段、超限请求 | 返回相应 JSON 错误，页面能解除加载状态并显示原因 |
| 只有一份获准读取的学生代码 | 可完成静态评审，同时显示“未提供参考实现” |
| 教师以获准使用的参考实现比较同一个示例文件 | 显示正确的对比方向和行数；评审页面不显示“已通过运行测试” |
| 教师读取所教班级的提交后，换用无权账号请求同一提交或评审编号 | 无权账号收不到代码和建议；把另一份作业的附件编号拼到请求中也无法读取 |
| 提交仅用于检查的脚本，例如第一行调用 `print` | 返回静态提示，`execution_performed` 为 `false`，服务端不会执行该输出语句 |
| 在教师⑨切换问答、算法和代码评审 | 问答显示五号返回的回答和引用或资料不足状态，算法显示六号返回的运行编号及状态，评审显示七号返回的问题位置和建议 |
| 点击独立助教首页各入口 | 调用各负责人提供的能力。问答显示引用或资料不足，算法显示运行编号及状态，学情只显示授权范围的数据 |

## 6. 当前进度和开发顺序

**已有本地原型**：Flask 提供粘贴文本评审、内存结果查询和两段文本的行差异比较。Vue 工作台已接入粘贴评审和建议展示；差异目前在 API 层。已编写 Docker Compose 启动配置，尚未进行系统联调和验收。

1. 先用虚构代码完善 Python 静态规则、差异页面和统一错误展示。用相同样例核对两个入口的评审结果。
2. 与 1、4、9 号用一份示例作业打通身份、提交版本、文件读取和评审记录存储，核对跨班级访问。和参考实现提供方确认来源后接入参考对比。
3. 七号负责教师⑨共用页面和独立助教首页的组装。先用模拟响应完成各入口状态，再联调 5、6、8 号提供的相应能力。集成验收记录使用的样例、版本、账号权限和预期结果。
