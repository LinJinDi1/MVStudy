# 机器视觉智慧学习平台

**领票从[开工索引](docs/development.md)开始，写代码先在下表找归属。** 正式平台共用一套 Flask 后端和一套 Vue 前端。一个业务域在两端使用同一个英文目录名；学生、教师和独立助教入口共用领域能力。

## 文件放在哪里

| 目录 | 放什么 |
|---|---|
| `backend/mvstudy/domains/<域>/` | 该域的 Python 业务、HTTP 入口、模型和测试。域内按用例命名，如 `experiments/submit_run.py`。 |
| `frontend/src/features/<域>/` | 该域的页面、组件、API 调用和测试。页面按操作命名，如 `experiments/RunExperimentPage.vue`。 |
| `backend/mvstudy/`、`frontend/src/` | 宿主装配：Flask 工厂、配置、数据库会话；Vue 启动、顶层布局、路由注册。01 号票首次接入登录。 |
| `migrations/versions/` | 全平台一条 Alembic 迁移历史；字段或约束的改动与所属业务票一起提交。 |
| `deploy/` | 整套平台的启动、配置示例和恢复操作，6 号维护。 |
| `tests/`、`tools/` | 跨模块场景、仓库结构检查及开发工具；单域测试放回该域。 |
| `modules/task-07/` | [评审演示启动入口](modules/task-07/README.md)。原 Compose 和本地启动命令复用正式前后端的 `review` 域；07 号在域内改规则，23 号接统一身份与持久化。 |

## 九个业务域

“负责的契约”是唯一实现方，字段、调用者和失败样例见[接口清单](docs/interfaces.md)。消费其他模块的接口不改变归属。

| 负责人 | 域目录名 | 负责的契约 | 功能归属 |
|---|---|---|---|
| [01](docs/task-01-spec.md) | `platform` | U1–U5、F1、P1 | 身份、班级、权限、受控文件、三类首页。首页读各域结果。 |
| [02](docs/task-02-spec.md) | `cases` | C1、C2 | 案例目录、材料可见范围、案例版本与算法绑定。 |
| [03](docs/task-03-spec.md) | `experiments` | A1–A3 | 算法登记、入队、进程执行、运行状态和产物。 |
| [04](docs/task-04-spec.md) | `teaching` | T1–T4 | 发布任务、固定应交名单、教师批改、成绩写入。 |
| [05](docs/task-05-spec.md) | `knowledge` | Q1 | 课程切分、检索、带来源回答和图像材料讲解。 |
| [06](docs/task-06-spec.md) | `assistant` | G1、H1 | 助教意图、追问、工具编排与健康探针；部署配置归 `deploy/`。 |
| [07](docs/task-07-spec.md) | `review` | R1–R3 | 静态评审、差异、教师助教及独立入口的页面组装。 |
| [08](docs/task-08-spec.md) | `analytics` | E1–E3 | 事件去重、指标口径、班级统计及周报。 |
| [09](docs/task-09-spec.md) | `submissions` | S1–S3 | 不可变提交、附件归属、源码读取及学生任务/成绩页。 |

## 例：6 号收到“帮我运行边缘检测”

1. **6 号**在 `assistant/` 识别意图、补齐图片和参数，按 A2 契约调用 **3 号**的提交运行能力。
2. **3 号**在 `experiments/` 完成参数校验、排队和运行记录写入。实验页的 A2 路由也调用这份实现。同一 Flask 进程内直接调用公开用例，保留调用者身份。
3. **7 号**的助教页面展示运行编号和进度。实验页与助教页需要相同结果视图时，复用 `features/experiments/` 导出的组件。
4. 测试各守一件事：6 号验证缺图追问、补图只提交一次；3 号验证非法参数不入队；跨模块场景用真实运行编号取回产物。

同理，9 号展示成绩时读 4 号的 T4，7 号读作业文本时用 9 号的 S3，首页展示完成率时读 8 号的 E2。

## 域内什么时候拆文件

| 变化 | 做法 |
|---|---|
| HTTP 请求和业务规则开始各自变化 | 路由文件只做解析、取得身份、调用用例及响应映射。将事务、授权和状态变化放在命名用例里，例如 `submit_run.py`；worker 和助教均复用它。 |
| Vue 页面同时处理表单、网络请求和结果呈现 | 保留页面做交互编排；把本域的请求放入 `api.ts`。结果面板出现第二个使用入口时再抽成组件。从域的 `index.ts` 导出供别域复用的组件或客户端。 |
| 另一个域要读取或改变业务状态 | 后端从提供方包的 `__init__.py` 导出必要用例，调用方通过 `mvstudy.domains.<域>` 导入；写操作仍由表的所有者完成。模型、私有函数留在域内。 |
| 有人准备增加“公共服务” | 先按上表找业务归属。只有不含教学业务规则、确有多个消费者的基础能力才放入共享层，例如前端 HTTP 传输；评分、权限、统计各保留一个业务来源。 |

无需给每个小功能预建 controller/service/repository 三层。评审时看**是否混入两种会独立变化的职责、同一条规则是否有两个写入点**，而不是看文件行数。

从仓库根运行 `python tools/check_layout.py` 检查文件落点和后端跨域内部导入；在安装了 `backend/requirements.txt` 的环境运行 `python -m unittest discover -s tests` 检查结构和评审入口。首次业务开工、联调及关票条件见[开发约定](docs/development.md)。
